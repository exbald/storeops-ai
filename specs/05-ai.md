# Agent and model specification

## Responsibilities

Use two Google ADK agents. The Investigator gathers evidence and proposes a diagnosis
and actions. The Execution Verifier evaluates new observations against the accepted
required state. Agents receive workspace-scoped tool handles and immutable references,
not database credentials. External content is untrusted data, including PDF text,
visit notes, product labels and image OCR.

Runtime module ownership belongs to T06 and T09. Neither agent may approve policies,
accept plans, mark records resolved, place orders, send messages, fetch arbitrary URLs
or execute model-authored SQL. Services own all state transitions.

## Inputs and tools

| Tool | Input | Output |
|---|---|---|
| get_sales_context | store_id, snapshot_id; windows/catalog are bound by the service | Complete/partial sales, fixed eligible peer set, freshness and source IDs |
| get_inventory_context | store_id, snapshot_id; catalog is bound by the service | Separate latest backroom/distributor rows with quantities, times and source IDs |
| get_approved_policy | frozen policy version ID | Reviewed rules, provenance and document/page references |
| get_visit_history | store_id, snapshot_id, limit ≤3 | Notes and observations before the snapshot, with source IDs |
| inspect_image | ready media ID, catalog reference IDs, required zone | ImageObservation matching the AI schema; no downstream conclusion implied |
| extract_policy | ready agreement media ID, catalog/store context | PolicyExtraction proposals; unknown clauses/gaps preserved for admin review |
| calculate_metrics | validated SalesContext | Deterministic Metrics DTO plus exact inputs, formula version and null reasons |

The exact tool schemas are in contracts/tools.json. Each tool returns status OK/MISSING/STALE/ERROR, data, evidence_ids and a safe error code.
The server supplies access scope and validates references. A tool's requested store ID
cannot broaden that scope. Prefer parallel independent reads within the run budget;
do not invent separate agents for every data source.

## Investigation procedure

1. Verify prerequisites and freeze source versions in the service layer.
2. Read policy, catalog, sales, stock and visit history; inspect each uploaded zone.
3. Validate structured observations and compute compliance/metrics in code.
4. Provide only validated evidence to the reasoning call. Require AnalysisProposal.
5. Check cited IDs, input scope, action kinds, rule IDs and schema. Reject numerical
   claims that conflict with the metric object. UI metric labels use the object, never
   numbers parsed from model prose. A repair cannot create missing evidence.
6. Persist the proposal and full evidence links; do not claim a proven root cause.

Hypotheses are EXECUTION, SUPPLY_CONSTRAINT, UNEXPLAINED_DECLINE, NO_ISSUE and
INSUFFICIENT_EVIDENCE. Healthy distributor stock with unknown backroom stock supports
CHECK_STOCK, not a factual assertion that the rep can replenish. A compliant shelf with
falling sales does not prove weak demand. Return alternatives and unresolved questions.

## Commercial math

For a run on store-local date D, current window is D−7 through D−1 and prior is D−14
through D−8. Use only complete product/date coverage and the same relevant catalog.
sales_delta = current_units / prior_units − 1. Store ratios as decimal strings; the UI
formats percentages. If prior_units=0 or coverage is incomplete, return null with reason.

Peers must share workspace, currency, retailer, region, store format, promotion and
complete windows. Exclude the focal store; require at least 3 peers with positive prior
units. peer_growth = sum(current_peer_units) / sum(prior_peer_units) − 1.
expected_units = prior_store_units × (1 + peer_growth).
opportunity_proxy = max(0, expected_units − current_store_units) ×
(prior_store_revenue / prior_store_units), rounded once to 2 decimals with HALF_UP.
Use Decimal arithmetic, preserve inputs and identify the formula as peer_gap_v1.

This is a weekly revenue gap proxy, not recoverable revenue, profit or measured impact.
When any prerequisite is missing, expected_units and opportunity_proxy are null; do not
invent peers or fall back silently to a fixed percentage or unit price.

## Images and verification

A facing is a distinct visible FRONT product position in the designated shelf block;
exclude stock depth. Product identity is a catalog product_id or unknown, never an enum
containing demo SKU names. Boxes use [ymin,xmin,ymax,xmax], integer 0–1000, ordered corners.
Deduplicate overlapping detections; unresolved identity or duplicates cannot establish
a compliant count. Count accepted detections in code, retain the raw observation and
record any correction as human review rather than an automatic result.

The display is a separate camera zone. Absence requires clear, unobstructed FULL coverage.
Unknown/partial coverage cannot become ABSENT. Feed after observations plus frozen rules
to the verifier; validation must reject unsupported PASS or missing/duplicate rule checks.
Code enforces per-rule predicates and computes the aggregate as defined in workflows.

## Model behavior and failure policy

Use JSON response schemas via Google Gen AI SDK; convert the canonical schema to the
provider's supported subset, while keeping strict application validation. A schema-valid
answer is not necessarily semantically true. Evidence and image evaluations are separate
release criteria. Do not log private chain-of-thought; progress is tool/event status.

Test models and thinking settings on development cases only before freezing the holdout.
Version prompts, schemas, model IDs, input references and settings for every call. Allow
one schema repair and bounded transient retry within the job budget. Report invalid
output, missing quota and timeouts explicitly. There is no fallback to a canned success.
